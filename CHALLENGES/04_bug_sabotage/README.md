# BUG SABOTAGE

Make working code.

Then let somebody RUIN IT.

Then race to repair it.

---

# PHASE 1 — BUILD

Everyone gets 15–20 minutes to make a small working program.

It can be:

- a tiny game
- calculator
- number guesser
- menu system
- combat system

It MUST work before sabotage begins.

---

# PHASE 2 — SABOTAGE

Trade programs.

The saboteur gets:

3 minutes.

They must introduce exactly:

# 3 BUGS

---

# SABOTAGE RULES

You MAY:

- change operators
- change comparisons
- change variable names
- move a line
- create bad logic
- create an error
- break a loop
- mess up a condition

You may NOT:

- delete the entire program
- replace everything with nonsense
- create impossible-to-see Unicode garbage
- remove every line
- intentionally destroy the file itself

The bugs should be FAIR.

---

# PHASE 3 — DEBUG

Return the program to its owner.

Timer:

10 minutes.

Fix all 3 bugs.

---

# WINNING

Fastest complete repair wins.

If nobody fixes all three:

most bugs fixed wins.

---

# BONUS MODE

For harder rounds:

- 5 bugs
- no debugger
- no print debugging
- one bug must be LOGIC ONLY

Logic-only means the program runs but behaves incorrectly.
