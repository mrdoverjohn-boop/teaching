# 50 PROGRAMMING CHALLENGES

This is a long-term challenge library for the teaching repo.

These are meant to be competitive, chaotic, reusable, and actually useful for learning programming.

---

# HOW TO USE THIS

- Pick challenges based on what everyone has learned.
- Do not force the hardest ones too early.
- Reuse challenges with different themes, teams, languages, or modifiers.
- A complete tiny game beats a giant broken project.
- For teacher-vs-students rounds, students can use Python while Bramity uses Rust or C.

---

# DIFFICULTY

- 🟢 **Beginner** — print, variables, input, math, if statements
- 🟡 **Early** — loops, random, lists, basic game state
- 🟠 **Intermediate** — functions, organization, planning, teamwork
- 🔴 **Advanced** — debugging, unfamiliar code, APIs, file I/O, architecture
- ☠️ **Final Boss** — everything together

# REUSING THE CHALLENGES

Most challenges can be repeated by changing:

- theme
- time limit
- team size
- language
- required mechanic
- surprise modifier
- line limit

So these 50 folders can easily become hundreds of actual rounds.

# HOUSE RULE

The technically hardest project does NOT automatically win.

If a tiny Python game is complete, funny, polished, and actually fun while a giant Rust project barely launches, the tiny game can win.

SHIP THE FUCKING GAME.
